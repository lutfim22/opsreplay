Demonstration and evidence preparation

Open the Pitch PDF and original successful AI screenshot before presenting. The screenshot belongs to the completed protected Preview test. Do not describe it as a new request or a mixed GitHub/IoT investigation.

The previous live-request allowance is consumed. Do not click Investigate with AI or Retry to rehearse, film or recover a presentation. Do not run a diagnostic workflow. The PDF/HTML documents and images make no AI requests when opened.

The AI Preview requires Vercel access. Show it only through the owner's normal access or use saved evidence. Do not disable protection, share browser sessions or create bypass links for an audience. Public Production AI remains OFF.

If GitHub is unavailable, show the warning honestly and continue with recorded evidence. Never fabricate GitHub activity. Opening or refreshing the running app can use GitHub API allowance; the document itself loads no remote assets.

Keep API keys, tokens, login state and environment settings out of screenshots/recordings. The product brief carries sources and qualifications; the technical handbook carries implementation limits. Use those documents for detailed follow-up rather than reading every caveat on stage.

Presenter Notes / 03

Buyer questions and honest answers

QuestionSuggested answer
Why should we care?When a device interrupts work, the team needs the right records and a clear next check. We want to test whether this workflow makes that easier.
Why not PagerDuty or Datadog?They are credible existing options. We have not proved superiority. A pilot should test fit and may conclude an existing tool is better.
Have you connected stores already?No. Retail multi-branch operations is a proposed starting use case. Current device data is simulated.
Is the 3D view working?The image is a concept illustration. Interactive 3D is future work and needs site/device mapping.
Is AI always correct?No. We validate response structure and event references, but a person must review the meaning and cause claims.
What improvement can you promise?No numeric improvement is established. We propose a baseline comparison before agreeing on a wider rollout.
Can we change the sources/model/rules?The code has separate boundaries, but new adapters and behavior need validation. Scope depends on the data and requirements.
What do you need from us?One real investigation task, permitted source data, an owner for the cases, and agreed access/spending/success criteria.
What does it cost and when is it ready?Price and schedule need requirements review. This proposal does not commit production service levels or delivery dates.

For 3D prioritization, ask whether people struggle to locate a device across sites. If their main problem is understanding the evidence, improve the timeline/data first. Do not make 3D a mandatory dependency for a useful pilot.
